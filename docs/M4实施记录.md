# M4 实施记录：每日发版、通知与回滚

更新时间：2026-11-05

## 1. 目标与链路

设计目标（第 4 周）：候选 Issue 通过 release 流程发布，失败可回滚，发布成功通知蓝信。不使用 GitHub Actions。

```
GitHub Issue（smartpipe:ready）
        │  GET /repos/{owner}/{repo}/issues?labels=smartpipe:ready
        ▼
admin-api  release.Execute
        ├─ 生成 Release Note（Issue 列表 + 作者 + 制品指纹）
        ├─ 干净克隆目标分支 HEAD（或指定 commit）→ 执行 smartpipe.yaml 的 build
        ├─ 创建轻量 tag（refs/tags/<version>）→ POST /repos/{o}/{r}/releases
        ├─ 回写标签：移除 ready、添加 released、在 Issue 评论发布链接
        └─ 通知蓝信群（bot /internal/reply）
        ▼
release_runs 表（候选集快照、Release Note、tag、Release URL、通知结果、耗时）
```

失败时（构建失败、tag 冲突、GitHub 报错）不消费候选 Issue、不创建 Release，制品与构建日志保留在 `output_dir`。

## 2. 接口

管理台（Bearer `SMARTPIPE_ADMIN_TOKEN`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/releases/candidates?project_id=&label=` | 读取候选 Issue（默认 `<prefix>:ready`） |
| POST | `/admin/releases/runs` | 执行一次发版；`dry_run=true` 只构建不发布 |
| GET | `/admin/releases/runs?limit=` | 发版运行记录 |
| GET | `/admin/releases/runs/{id}` | 单条记录（含 Release Note 与构建输出） |
| POST | `/admin/releases/runs/{id}/rollback` | 回滚：删 Release 与 tag，候选 Issue 恢复 ready，通知蓝信 |
| POST | `/admin/releases` | 保留的“仅构建”入口（不发布、不改标签） |

`POST /admin/releases/runs` 请求体：

```json
{
  "project_id": "prj_xxx",
  "version": "v2026.11.05",
  "commit": "",
  "branch": "",
  "notes": "升级提示",
  "dry_run": false,
  "artifact_globs": ["dist/**", "bin/**"],
  "ready_label": ""
}
```

* `commit` 留空取 `branch`（默认项目 `github_default_branch`）HEAD。
* `artifact_globs` 留空使用 `dist/**`、`bin/**`、`build/**`；无匹配制品判失败。
* 版本号只允许 `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`，防止路径逃逸。

返回 `run.status`：

| 状态 | 含义 |
|---|---|
| `skipped` | 没有候选 Issue，未构建 |
| `built` | Dry Run 构建成功，未发布 |
| `failed` | 构建/发布失败；候选未消费 |
| `released` | tag、Release、标签回写、通知全部完成 |
| `released_with_warnings` | 发布成功，但部分 Issue 标签或评论失败（详见 `error`） |
| `rolled_back` | 已回滚 |

## 3. 每日定时

`SMARTPIPE_RELEASE_SCHEDULE=06:00` 开启内置定时器（本地时区，30 秒粒度）。每个启用的项目每天跑一次，版本号 `vYYYY.MM.DD`；同一项目同一天同一版本只执行一次，触发来源记为 `scheduled`。没有配置则关闭，由外部 Automation 调用 `POST /admin/releases/runs` 也可以。

## 4. 数据表

```sql
CREATE TABLE release_runs (
    id BIGSERIAL PRIMARY KEY,
    project_id TEXT,
    version TEXT NOT NULL,
    commit_sha TEXT NOT NULL DEFAULT '',
    branch TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL DEFAULT '',
    trigger TEXT NOT NULL DEFAULT 'manual',
    candidates JSONB NOT NULL DEFAULT '[]'::jsonb,
    notes TEXT NOT NULL DEFAULT '',
    release_url TEXT NOT NULL DEFAULT '',
    tag TEXT NOT NULL DEFAULT '',
    release_id BIGINT NOT NULL DEFAULT 0,
    manifest_sha256 TEXT NOT NULL DEFAULT '',
    output_dir TEXT NOT NULL DEFAULT '',
    artifacts JSONB NOT NULL DEFAULT '[]'::jsonb,
    build_output TEXT NOT NULL DEFAULT '',
    error TEXT NOT NULL DEFAULT '',
    notify_status TEXT NOT NULL DEFAULT '',
    notify_error TEXT NOT NULL DEFAULT '',
    started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at TIMESTAMPTZ,
    duration_ms INTEGER NOT NULL DEFAULT 0
);
```

## 5. 端到端实测（2026-11-05）

环境：Windows 本地 admin-api(:8092) + 真实 Postgres(192.168.1.99) + 假 GitHub(:9099) + 假蓝信 bot(:9091) + 本地沙箱仓库 `.dev/release-repo`。

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\release-smoke.ps1
RELEASE SMOKE OK project=prj_5148b505
  skipped=25 dry=26 released=27 rolled=27 failed=28
  tag=v0.9.3@2d06bbc12fed2c23a7280667ef9a1fb9400a1cef
  release_url=http://127.0.0.1:9099/releases/5002
```

覆盖：

1. 无候选 → `skipped`，不构建。
2. 两个 `smartpipe:ready` Issue → Dry Run `built`，假 GitHub 上无 tag、无 Release。
3. 正式发布 → `released`：tag 指向仓库 HEAD、Release Note 含 `#101` 与自定义说明、Issue 标签变为 `smartpipe:released`、蓝信群 `grp-release` 收到通知。
4. 回滚 → `rolled_back`：Release 与 tag 被删除，Issue 回到 `smartpipe:ready`，蓝信收到回滚通知。
5. 指定不存在的 commit → `failed`：不创建 Release，候选 Issue 保持 `smartpipe:ready`。
6. 记录写入 `release_runs`，`GET /admin/releases/runs` 可查。
