# 蓝信多机器人管理实施记录

日期：2026-11-08  
范围：蓝信配置页重构、多机器人管理、自动同步所在群、机器人详情/消息页、项目创建时选择群。

## 1. 页面职责

蓝信页只负责机器人本身：

- 添加、编辑、停用、删除多个蓝信个人机器人；
- 添加机器人后立即连接测试并同步其所在群；
- 每次打开蓝信页或项目页时自动刷新机器人状态和群快照；
- 机器人列表展示连接状态、群数量、消息数量和最近同步时间；
- 点击机器人进入详情页，查看它所在的群和最近 100 条聊天/建单消息。

群到项目的绑定移出蓝信页。新增或编辑项目时，先选择蓝信机器人，再从该机器人已同步的群中选择群。已经被其他项目占用的群不会出现在可选列表中。

## 2. 数据模型（迁移 22）

| 表/字段 | 用途 |
|---|---|
| `lanxin_bots` | 机器人名称、凭据引用、App ID、API Base、@ 规则、启停、连接状态、最近同步/错误 |
| `lanxin_groups` | 每个机器人所在群的最新快照；`active=false` 保留最后一次可见后的历史 |
| `lanxin_messages.bot_id/bot_name` | 消息与接收消息的机器人关联 |
| `projects.lanxin_bot_id` | 项目选择的机器人；`bluex_group_ids` 保留选中的群 |

迁移会把旧单机器人凭据自动转换为 `lbot_legacy` “主机器人”，旧项目自动补上该机器人 ID 和历史消息的机器人归属。

机器人 App Secret 继续存放在现有 `credentials` 表并通过 AES-GCM 加密；机器人表只持有 `credential_id`。

## 3. 后端接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/admin/lanxin/bots?sync=1` | 机器人列表；`sync=1` 自动刷新所有启用机器人的群 |
| POST | `/admin/lanxin/bots` | 添加机器人，保存后立即同步群 |
| GET | `/admin/lanxin/bots/{id}?sync=1` | 机器人详情，包含群和最近消息 |
| PATCH | `/admin/lanxin/bots/{id}` | 修改名称、凭据、API Base、@ 规则 |
| DELETE | `/admin/lanxin/bots/{id}` | 删除机器人与凭据 |
| POST | `/admin/lanxin/bots/{id}/enabled` | 启用/停用 |
| POST | `/admin/lanxin/bots/{id}/test` | 获取 app token、测试连接并同步群 |
| POST | `/admin/lanxin/bots/{id}/sync-groups` | 手动刷新单个机器人群 |
| GET | `/admin/lanxin/groups?refresh=1` | 项目页可选群；`refresh=1` 先刷新所有机器人 |
| GET | `/admin/lanxin/messages?bot_id=` | 全局或按机器人查询消息 |

内部接口：

- `GET /internal/lanxin/bots`：bot 进程读取所有启用机器人的运行时配置；
- `POST /internal/lanxin/bots/{id}/status`：bot 上报 connecting / connected / disconnected / error。

## 4. 自动群同步

群同步完全使用蓝信 API：

1. `GET /v2/groups/fetch` 分页读取机器人所在群 ID；
2. 对每个群调用 `GET /v2/groups/{id}/info/fetch` 获取群名称、群主、成员数和发送状态；
3. 事务写入 `lanxin_groups`，本次未出现的旧群标记 inactive；
4. 前端不需要用户填写任何群 ID。

企业部署如果 `/v2/groups/fetch` 权限不足，机器人仍可保存并连接，错误会写入 `last_sync_error` 显示在页面。

## 5. 多 WebSocket 运行

bot 进程现在维护一个机器人运行时表：

- 每 30 秒从配置台读取机器人列表；
- 新机器人启动独立 WebSocket；
- 凭据、API Base、@ 规则变化时停止旧连接并重建；
- 停用/删除机器人时停止对应连接；
- 每条入站消息、建单记录和群回执都携带 `bot_id`，回执选择原消息所属机器人发送。
