# 模型配置与 Codex 导入实施记录

## 页面结构

配置台导航和页面标题统一为「模型配置」。页面分为两部分：

- 模型 Profile：保存 Profile 名称、模型、供应商和推理强度的组合，可启停、设为默认或删除。
- 模型供应商：保存连接地址、API 协议、加密 API Key 和模型目录。

原有「手动添加」供应商表单继续保留。

## 本机 Codex 配置导入

导入窗口对齐 Syntropy 的交互：

1. 选择本机 `~/.codex/config.toml`。
2. 选择 `~/.codex` 或其他目录，自动查找其中的 `config.toml`；目录内存在多个文件时可选择具体路径。
3. 在页面中直接粘贴或编辑 Codex TOML。

读取配置后展示两张可选表格：

- Profile：Profile 名称、Model、Provider、推理强度和 API Key 来源。
- Provider：Provider 名称、Base URL、API 格式和 API Key 来源。

Profile 勾选时会自动勾选其依赖的 Provider；取消 Provider 时会同时取消依赖它的 Profile。底部按钮实时显示选中的 Profile/Provider 数量。只导入勾选项，导入的 Profile 和对应模型默认启用。

## 导入字段

后端读取：

- 顶层 `profile`、`model`、`model_provider`、`model_reasoning_effort`
- `[profiles.<name>]`
  - `model`
  - `model_provider`
  - `model_reasoning_effort`
- `[model_providers.<id>]`
  - `name`
  - `base_url`
  - `wire_api`
  - `experimental_bearer_token`
  - `api_key`
  - `env_key`
  - `requires_openai_auth`

API Key 来源在预览中标记为 `TOML`、`已保存`、`ENV` 或 `未提供`。`experimental_bearer_token` 或 `api_key` 会进入现有加密凭据库，接口不会返回明文。`env_key` 只保留变量名并提示需要补充，因为浏览器和服务端不会读取使用者本机的环境变量。

选择配置中的默认 Profile 且供应商已有可用密钥时，会同步切换系统默认模型和推理强度。

## API

- `POST /admin/model-config/import/preview`
- `POST /admin/model-config/import`
- `GET /admin/model-profiles`
- `POST /admin/model-profiles/{id}/enabled`
- `POST /admin/model-profiles/{id}/default`
- `DELETE /admin/model-profiles/{id}`

导入请求体：

```json
{
  "source": "~/.codex/config.toml",
  "content": "...",
  "profile_keys": ["qax"],
  "provider_keys": ["deepseek"]
}
```

Profile 依赖的 Provider 会自动加入导入集合。预览和导入响应都不包含 API Key 明文。
