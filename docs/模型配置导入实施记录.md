# 模型配置与 Codex 导入实施记录

## 页面调整

配置台导航和页面标题统一为「模型配置」，继续保留供应商连接、模型目录、默认模型与推理强度管理。

页面新增三种录入方式：

1. 选择本机 `~/.codex/config.toml`。
2. 选择 `~/.codex` 或其他目录，自动查找其中的 `config.toml`；目录内存在多个文件时可选择具体路径。
3. 在页面中直接粘贴或手动编辑 Codex TOML。

原有「手动添加」供应商表单继续保留，可填写名称、API 格式、Base URL、API Key 和初始模型。

## 导入规则

后端读取顶层字段：

- `model`
- `model_provider`
- `model_reasoning_effort`
- `review_model`
- `[model_providers.<id>]`
  - `name`
  - `base_url`
  - `wire_api`
  - `experimental_bearer_token`
  - `api_key`
  - `env_key`
  - `requires_openai_auth`

导入时按供应商名称创建或更新记录。`experimental_bearer_token` 或 `api_key` 会进入现有加密凭据库，接口不会返回明文。`env_key` 只保留变量名并给出提示，因为浏览器和服务端无法读取使用者本机的环境变量。

顶层 `model` 与 `review_model` 会加入当前 `model_provider` 的模型目录。只有当前供应商存在可用凭据时，才切换系统默认模型与推理强度。

## API

- `POST /admin/model-config/import/preview`
- `POST /admin/model-config/import`

请求体：

```json
{
  "source": "~/.codex/config.toml",
  "content": "..."
}
```

预览响应只包含供应商、连接地址、协议、是否提供密钥、模型和提示，不包含密钥值。
