# 在线测试部署与验收

当前代码已具备本机 MCP 网关、一次性 TS Worker、后端机器租约/任务/证据及 V2 发布策略检查、管理台只读观察入口。尚未完成真实安装/编码/升级场景，不应称为完整发布验收环境。

## 控制端

1. 对专用测试数据库执行现有 Store.Migrate，新增迁移44–47随 admin-api 启动路径执行（按实际部署入口确认）。
2. 构建 admin-api 和 web，部署在 HTTPS 后。
3. 管理台“在线测试”查看机器和任务；创建观察任务须填实际项目、源码 SHA、制品 SHA256。
4. 管理身份 POST /admin/test-machines，body 为 {"platform":"windows-amd64"} 或 darwin-arm64 等。机器令牌仅在首次响应返回，应通过部署工具安全注入测试机，不能放在聊天、项目配置或提交中。
5. 测试机只访问 /test-runner/*，无需管理员令牌。

## 测试机

- 专用交互桌面，运行与被测 Syntropy 独立的 Runner。
- 固定 Qwen Node REPL 0.27.0 及匹配原生运行时。当前项目不自动安装上游。
- 完成操作系统的截图及辅助功能授权。
- 预安装并启动被测 Syntropy；当前 worker 不执行安装。
- 在 test-runner 运行 npm ci --ignore-scripts 与 npm run build。
- 根据 worker.example.json 设置 API、机器ID、状态目录、本地制品、应用名、Node/上游入口的绝对路径。
- 由部署环境注入 SMARTPIPE_TEST_MACHINE_TOKEN。
- 执行 node dist/src/worker-cli.js <配置文件>，一次执行一条任务。
- 从管理台下载观察证据，检查画面确实来自目标应用。

desktop-observe@1 只证明应用可观察，不证明其运行版本与制品匹配，不允许作为发布门禁策略。

## 专用数据库集成测试

有 Docker 的隔离开发机可运行：
powershell -NoProfile -File scripts/test-online-db.ps1

脚本只建立新的 postgres:17 容器，监听127.0.0.1:55439、使用 smartpipe_online_test，测试结束停止该容器；不读取业务连接，不清理现有数据库。Docker镜像版本按17系列拉取，正式CI应再固定镜像摘要。
脚本覆盖 TestDesktop*（状态流转、租约代次、证据、制品门禁），暂不运行会清理共享表的多包并行集成测试。
当前环境只通过脚本语法解析，未运行容器。

## V2 门禁

GET/POST /admin/projects/{id}/test-gate 管理策略数组：
[
 {"scenario":"installed-code-fix","version":"1","platform":"windows-amd64","artifact_role":"installer","required_checks":["installed_version_matches","fixture_tests_pass"]}
]

这是未来完整场景的策略示例；installed-code-fix 执行器尚未实现，不要直接启用后期待任务自动完成。
未配置或空策略不拦截；配置后 promote/github_release_publish 会核对同制品、同源码、同场景版本及当前必测项。读取失败阻断。
需在投产前进一步核对旧版发布通道、远端发布对象一致性及并发发布锁；不能把现有V2两处检查理解成全部发布路径均已封闭。

## 尚需实机输入

用户需指定专用 Windows 与 Mac 测试机以及独立测试数据库或 Docker 主机；连接凭据通过平台账号连接或部署流程提供，不在对话中传递。
