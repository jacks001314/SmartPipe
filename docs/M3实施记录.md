# M3 实施记录：批准门禁与派生入口

更新时间：2026-11-05

## 1. 门禁语义

复杂 Issue 必须先有服务端认可的批准，才允许进入实现与派生。判定规则（`internal/gate`）：

| 情况 | 结果 |
|---|---|
| 该 Issue 没有任何 `issue_plans` 记录 | 视为简单任务，直接放行（`required=false`） |
| 有方案记录，但没有对应版本的批准 | 拒绝：`approval_required`，说明「plan vN has no approval yet」 |
| 有批准，但方案正文哈希与登记值不一致 | 拒绝：方案内容被修改，旧批准失效 |
| 有批准且哈希一致 | 放行，返回审批人、版本与 `plan_hash` |

Issue 引用支持 `owner/repo#123`、`#123`、`123`；只给编号时使用项目配置的 `github_issue_repo`。

## 2. 拦截点

1. **补丁验证** `POST /admin/verifications`：提交补丁前先过门禁，未批准直接返回 403，并写审计 `patch.verify result=blocked`。
2. **子 Agent 派生** `POST /admin/derivations`：lead 派生子 Agent 的唯一入口。
   - 先查门禁；
   - 通过后用项目绑定或显式 `app_server_id` 调 App Server `POST /api/agents`；
   - 记录 `derivations`（agent_id、operation_id、批准版本与哈希）；
   - 返回 operation 与批准快照。

`GET /admin/derivations?limit=` 供管理台与审计查询。

## 3. 数据表

```sql
CREATE TABLE derivations (
    id BIGSERIAL PRIMARY KEY,
    project_id TEXT,
    issue_ref TEXT NOT NULL DEFAULT '',
    agent_name TEXT NOT NULL DEFAULT '',
    agent_id TEXT NOT NULL DEFAULT '',
    operation_id TEXT NOT NULL DEFAULT '',
    approval_version INTEGER NOT NULL DEFAULT 0,
    approval_hash TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL DEFAULT '',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 4. 端到端实测

Issue `example/core#200`：

1. `/plan` 登记 v1，哈希 `sha256:d7c4617d...`。
2. 未批准时提交补丁验证：`HTTP 403 {"code":"approval_required","message":"plan v1 has no approval yet"}`。
3. 维护者 `/approve v1`（OWNER）→ 202 approved。
4. 再次验证：200，`ok=true`，build/unit 均通过。
5. `POST /admin/derivations` 派生 `dev-issue-200b`：
   ```json
   {"agent_id":"agent-8ae52282e8aadb86fea6dc68",
    "operation_id":"op-e45529b503da446cbf2907d9",
    "approval_version":1,
    "approval_hash":"sha256:d7c4617d..."}
   ```
   App Server 返回操作 `state=2`（部署中），记录写入 `derivations`。

Issue `example/core#201`（有方案、未批准）：派生直接 `403 approval_required`，不会创建任何 Agent。
