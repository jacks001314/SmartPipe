### TS 本机 MCP 网关

### 后端测试运行（本轮）
新增 internal/testlab，定义 Spec、Report、Check、Run 及服务端 Evaluate。
输入绑定 project_id、完整 source_sha、artifact_sha256、scenario、scenario_version、platform 和 required_checks。
必测项全部 PASS 且有证据引用才能计算 PASS；缺项、SKIPPED、BLOCKED 或空证据均计算 BLOCKED。重复检查项及身份不匹配拒绝。
MatchesPassedRun 使用调用方当前策略重新检查报告，不能通过旧报告绕过新增必测项。目前只是判定函数，尚未挂入实际发布入口。

数据库迁移 44 新增 desktop_test_runs。状态：
QUEUED → RUNNING → PASS / FAIL / BLOCKED
QUEUED / RUNNING → CANCELLED
最终报告以数据库 compare-and-set 写入，迟到报告不能覆盖取消或其他终态。
项目引用默认限制删除有验收记录的项目，以保留测试追溯；删除策略后续需在管理台说明。

管理 API（沿用现有 /admin 认证与审计）：
- POST /admin/test-runs
- GET /admin/test-runs/{id}
- POST /admin/test-runs/{id}/start
- POST /admin/test-runs/{id}/cancel
- POST /admin/test-runs/{id}/report

这些是管理端登记接口，不是桌面机器认证接口。暂不向 Runner 下发管理员令牌。
当前证据只校验引用非空，尚未验证证据对象存在或可信，因此不得作为生产发布放行依据。

## 续跑第二轮：机器租约与 TS 远程执行

- 迁移45：desktop_test_machines，运行表绑定 machine_id / lease_generation。
- 管理端机器登记和列表；随机机器凭证只返回一次、数据库保存哈希。
- 独立机器认证接口 /test-runner/*，即使 admin DevOpen 也不放开机器接口。
- 事务锁定机器和待执行任务，generation 递增；并发领取使用 SKIP LOCKED。
- 续租及报告要求身份、任务、代次、租约时间和运行状态同时匹配。
- 过期机器保留忙状态；完成报告后仍需清理确认 release，不会立即被复用。
- 原管理上报接口禁止直接完成 machine_id 非空的任务，防止绕过机器租约。
- TS RunnerClient：HTTPS（本机开发例外）、拒绝重定向、15秒心跳、失联取消、不重试副作用、先清理后报告再释放。
- ObserveScenario：Qwen Node REPL MCP 读取应用控件树与截图，本地制品哈希预检、证据保存；上游不继承机器令牌。
- worker-cli.ts 和 worker.example.json 提供一次性运行入口。

验证：npm test 8/8通过；go test ./internal/testlab ./internal/store ./internal/adminapi -count=1通过可执行测试。
新增 PostgreSQL fencing 集成测试，但专用测试库仍未配置，不能声称行锁/SQL实测通过。
TS HTTP测试使用受控HTTP测试服务，不是完整 Go+PostgreSQL+Qwen 真机联调。

重要限制：当前场景只诊断桌面可观察，无法证明运行中的安装版本和制品一致；证据仍保存在测试机而未可信上传；发布门禁仍未启用。
已向用户询问专用 Windows/Mac 测试机及测试库信息，在收到前继续实现不依赖实机的部分。

## 续跑第三轮：上传证据和 V2 发布门禁

已新增迁移46：desktop_test_evidence，保存按运行隔离的证据字节、MIME和SHA256。单件8MiB、每轮64MiB，上传要求有效机器身份、运行和租约代次；后端重算哈希，重复同哈希上传幂等。管理端下载使用 no-store/nosniff/attachment。
机器完成报告时，所有 PASS 检查必须引用该运行已上传的 sha256: 证据；仅本地路径不再接受。证据存在不等于语义验收独立可信：截图内容与业务断言仍需后续独立检查器。
TS 场景清理后、报告前上传截图并核对回执哈希；上传失败不提交成功、不释放机器。阻止已过期 assignment 开始执行。

已新增迁移47：项目级 desktop_gate_policies。
GET/POST /admin/projects/{id}/test-gate 读写策略，沿用管理认证和审计。
策略字段：scenario、version、platform、artifact_role、required_checks。
明确禁止 desktop-observe 作为发布策略，避免截图连通性冒充产品验收。
V2 releasemcp 的 promote 和 github_release_publish 已在副作用前调用 CheckDesktopReleaseGate：
按项目、已解析源码SHA、制品SHA、场景版本、平台匹配已完成机器运行，并检查当前必测项和上传证据。
策略不存在/空列表时不启用；读取数据库失败则阻断。尚未对实际项目设置策略。
旧版 release 链路、远端 GitHub draft/升级服务制品一致性以及最终并发发布锁仍需整体核对，当前不可宣称覆盖所有发版通道。

验证：npm test 10/10成功；Go testlab/store/adminapi/releasemcp 可执行测试通过。
新增真实数据库证据上传/报告集成测试，但没有 SMARTPIPE_TEST_DSN，因此明确 SKIP。
尚无 Windows/Mac 原生实机执行、真实安装/升级或发布操作；用户尚未回复测试机与测试库选择。

## 续跑第六轮：机器停用/恢复和整轮时限

- POST /admin/test-machines/{id}/enabled：停用机器并原子取消占用运行；拒绝新认证/续租/结果，保留占用记录。
- POST /admin/test-machines/{id}/recover：仅停用机器可恢复，要求准确generation、cleanup_confirmed=true及原因；恢复递增代次并保持停用，之后显式启用。
- 管理台支持停用/启用；待清理的机器禁用启用按钮。
- Runner新增20分钟绝对执行时限，成功心跳不能延长；超时取消场景并保留机器待恢复。
- npm test 15/15通过，包含健康心跳下的绝对超时；web build通过；Go相关测试通过可执行项。
- 数据库恢复测试已补但仍需真实PostgreSQL执行。停用只阻止API，不代表系统层立即杀掉GUI进程；受控Worker在续租失败时停止，管理员仍须核对本地清理。
