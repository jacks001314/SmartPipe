# 蓝信消息收集实施记录

日期：2026-11-08
范围：蓝信应用配置、WebSocket 入站消息、收件箱落库、群到项目绑定、建单与回执。

## 1. 目标

把“蓝信配置 → 收消息 → 建 Issue → 群回执”做成可观测的闭环。此前控制台的“最近消息”只读
`bridge_links`，未 @ 机器人、群未绑定项目、非文本消息在 bot 过滤后没有任何记录，排查时看不到
“消息到底有没有收到”。

## 2. 收件箱

新增表 `lanxin_messages`（迁移 21）：

| 字段 | 说明 |
|---|---|
| `platform_message_id` | 蓝信 msgId，唯一键，重复上报只刷新描述字段 |
| `chat_type` / `chat_id` / `group_name` | 会话信息 |
| `user_id` / `sender_name` | 发送人 |
| `msg_type` / `text` / `is_at_me` | 消息内容与 @ 状态 |
| `project_id` | 按群绑定解析出的项目 |
| `status` / `reason` | 处理结果与原因 |
| `issue_number` / `issue_url` | 建单结果 |

状态取值：

| status | 含义 |
|---|---|
| `received` | 已收到，等待处理 |
| `filtered` | 主动忽略（未 @、非文本、命令） |
| `unbound` | 群/会话没有绑定项目 |
| `issue_created` | 已建 GitHub Issue |
| `failed` | 建单或上游调用失败，原因见 `reason` |

写入路径：

- `/bridge/messages`：可建单的消息先写收件箱，再建单；成功更新为 `issue_created`，未绑定写
  `unbound`，失败写 `failed`。
- `/bridge/inbound`：bot 对未进入建单流程的消息上报过滤原因（未 @、非文本、命令）。
- 同一 msgId 重复上报不会把 `issue_created` 降级。

## 3. 控制台

「蓝信配置 → 最近消息」改为读 `GET /admin/lanxin/messages`，展示时间、会话、发送人、内容摘要、
项目、Issue、状态与原因。`limit` 默认 50，最大 200。

## 4. 配置链路的两个加固

- 保存配置时拒绝把 `http://` / `https://` 开头的值存进 App Secret。
- 连接测试发现已保存的 Secret 是 URL 时，直接提示“旧配置残留，请重新粘贴密钥”，
  避免只报 DNS/鉴权错误。

## 5. 本地端到端验证

环境：临时 Postgres（端口 55432）+ 本地 admin-api(18092) / bridge(18090) / bot(18093) +
假蓝信 HTTP/WebSocket(19094) + 假 GitHub(19099)。

| 场景 | 结果 |
|---|---|
| 配置保存 → bot 启动 | 日志 `已从配置台加载蓝信应用配置`，WebSocket connected |
| @机器人 的群消息 | Issue #101 创建，标签 `source:bluex`、`smartpipe`，群内回执带 Issue 链接 |
| 未 @ 的群消息 | 收件箱 `filtered`，原因“群消息未 @ 机器人”，不建单 |
| 未绑定群的消息 | 收件箱 `unbound`，原因“群/会话未绑定项目”，群内回执提示先绑定 |
| 正常 @ 消息（第二条） | Issue #102/#103，收件箱 `issue_created`，发送人与群名完整 |
| 重复 msgId | 不重复建单 |

数据库验证：

```sql
select platform_message_id, chat_id, status, reason, issue_number
from lanxin_messages order by created_at desc;
```

## 6. 真实报文兼容（2026-11-08）

线上真实网关的部分消息报文不带 `data.chatType`，旧解析会把会话类型留空并丢弃消息。bot 现在
按事件类型兜底：`bot_group_message` → `group`，`bot_message` → `p2p`；字段缺失时把原始
`data`（截断 2KB）写进日志，便于对照协议。未知会话类型也会进收件箱（`filtered`）。
